SOC Copilot: does it resist prompt injection?

A small language model (Llama 3.2 3B) rates security alerts. We attacked it with 34 unseen injection attempts under four setups. Prompt hardening helped, regex guardrails did not generalise, and planted notes could still make severe alerts look harmless.

How it works

Each alert passes through these stages. Setups A–D switch stages on one by one.

AlertRaw SIEM text, which may hide an attacker’s instructions
Input guardRegex scan for known injection phrases (D only)
ModelReturns severity, technique, CVEs and a rationale
Output checkValidates the format, flags unknown CVEs (D only)
Severity floorProposed: rules set a minimum, the model can only raise it

Guardrails fit the known attacks

Share of attacks the input regex blocked.

The regex was written against the first attack set. On new phrasings and other languages it blocked almost nothing, and D’s results matched C’s.

Planted notes lowered severity

Severe alerts rated low (of 5), with and without a note such as “approved pentest”.

With the note, every setup said low. Without it, C and D never did. That is why the design adds a rule-based severity floor.

Limits. One run, one 3B model, 34 attacks written after the guardrail code was read, single-rater labels, five alerts in the downgrade control. Treat the numbers as direction, not rates.
